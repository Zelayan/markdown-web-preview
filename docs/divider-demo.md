# 分隔线阅读效果

这份文档用于检查 `---` 在浅色、深色主题下的显示效果。正常情况下，分隔线是一条与正文同宽的细灰线，上下有适度留白，不跟随强调色变化。

## 日常阅读

发布前确认目标版本、运行状态与备份记录。每个阶段用分隔线划分，让较长的操作说明更容易浏览。

---

检查完成后，在维护窗口执行变更。观察日志和健康接口，确认没有新增异常，再继续后续步骤。

---

执行结束后记录时间、版本和验证结果；出现问题时，根据备份执行回滚。

## 标题之间的分隔

### 发布前检查

- [x] 配置校验通过
- [x] 已完成必要备份
- [ ] 确认维护窗口

---

### 发布后验证

- 服务处于正常运行状态。
- 健康接口返回预期结果。
- 日志中没有新增错误。

## 表格与代码之间的分隔

| 检查项 | 预期结果 | 异常处理 |
| --- | --- | --- |
| 服务状态 | `active (running)` | 检查启动日志 |
| 健康接口 | 返回 `200` | 确认端口和依赖 |
| 配置版本 | 与目标版本一致 | 恢复已备份的配置 |

---

```bash
systemctl status example.service
journalctl -u example.service --since "10 minutes ago"
```

---

> [!NOTE]
> 可以切换亮色、暗色和强调色，对比分隔线是否仍然保持安静的灰色。

## 语法对照

下面这行采用标准的 Setext 二级标题写法：文字后紧跟 `---`，没有空行，因此应显示为标题，并进入左侧大纲，而不是分隔线。

这是二级标题，不是分隔线

这是一段普通正文。

## 检查清单

- [ ] 横线与正文内容区同宽，不延伸到大纲。
- [ ] 亮色与暗色下都能看见，但不抢正文注意力。
- [ ] 切换蓝色、绿色等强调色后，横线仍然是灰色。
- [ ] 上下留白自然，不出现厚边框、阴影或渐变。
- [ ] 表格分隔符和代码块里的 `---` 没有被误处理。
- [ ] PDF 打印版使用细灰线。

此文档不包含 YAML Frontmatter，避免将元数据解析问题与分隔线样式混淆。
